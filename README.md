# 局域网 HTTPS 文件共享(lan-file-share)

**中文** | [English](README.en.md)

一个**开箱即用**的 Node.js 程序:把你电脑上的一个文件夹以 HTTPS 方式共享出来,局域网内的
手机 / 平板 / 其它电脑用浏览器打开一个网址,就能浏览目录结构并**下载 / 上传**文件。

> 另有三个可选依赖用于增强「低清预览 / 批量打包 / WebDAV 挂载」体验(见下表)。
> 服务默认按 **IPv4 + IPv6 双栈**监听(系统没启用 IPv6 时自动退回 IPv4),
> 启动时会把本机各局域网地址(含 IPv6)都列出来;还可以在网页端给**主共享**加一道
> 「根目录访问密码」,让局域网设备访问前先输密码(见[第七节](#七根目录访问密码可选仅保护局域网访问))。

---

## 一、这是什么 / 你要准备什么

| 依赖 | 说明 |
|------|------|
| Node.js `>=18` | 运行服务器本体 |
| `sharp`(可选) | 生成图片低清预览图。装了预览更快、更省流量;不装则预览直接加载原图 |
| `ffmpeg`(可选) | 为视频抽取封面帧。装了视频在列表里显示封面、可点开播放;不装只显示 🎬 图标 |
| `archiver`(可选) | 批量下载时打包成 ZIP。不装则「下载选中」不可用,单文件下载不受影响 |
| `webdav-server`(可选) | 把分享目录同时以 WebDAV 协议暴露(可在系统里「映射网络驱动器」)。当前属试验特性,Windows 客户端支持尚不完善;不装则仅网页访问 |
| OpenSSL | 仅**首次**生成自签名证书需要;Windows 上可用 Git for Windows 自带的 openssl |

> 本项目核心功能零依赖(仅用 Node.js 内置模块)。以下依赖均为**可选增强**,
> 首次使用建议在该目录执行一次 `npm install`;不装也能正常跑,只是对应功能不可用
> (预览退回加载原图、批量下载不可用、WebDAV 关闭)。

项目文件如下:

```
lan-file-share/
├─ server.js        # HTTPS 服务器主程序(浏览+下载+上传+实时同步+单独分享+访问密码+操作日志)
├─ gen-cert.js      # 生成自签名 HTTPS 证书(含本机各局域网 IPv4 / IPv6 地址的 SAN)
├─ start.bat        # 【推荐】Windows 一键启动(缺证书会自动先生成)
├─ setup.bat        # 【推荐】Windows 一键安装(装依赖 + 生成证书 + 启动)
├─ setup.sh         # Linux / macOS 一键安装(同上流程)
├─ config.json      # 配置:共享目录、端口、上传大小上限、日志级别等
├─ shares.json      # 单独分享的记录(首次分享后自动生成;仅存口令哈希)
├─ rootauth.json    # 主共享「根目录访问密码」的记录(在网页端设置后生成;仅存 scrypt 哈希)
├─ package.json     # npm start / npm run cert / npm install 依赖
├─ LICENSE          # GPL-3.0 许可证全文
├─ README.md        # 中文说明(英文版见 README.en.md)
├─ README.en.md     # English documentation
├─ node_modules/    # 依赖(sharp / archiver / webdav-server)——由 npm install 生成
├─ certs/           # 首次运行自动生成的证书(server.crt / server.key)
└─ share/           # 默认的共享目录(想共享哪个文件夹就改 config.json)
```

## 二、快速开始(推荐)

### 方式一:一键安装(推荐)

双击 **`setup.bat`**(Windows)或在终端执行 **`./setup.sh`**(Linux / macOS),它会自动:

1. 检查是否装了 Node.js(没有会提示你去 https://nodejs.org/ 下载)
2. 安装可选依赖 `sharp` / `archiver` / `webdav-server`(已装则跳过)
3. 生成 HTTPS 自签名证书(已有则跳过)
4. 创建默认共享目录 `share/`(若不存在)
5. 启动服务器并打印访问地址

> 重复运行是安全的:已完成的步骤会自动跳过,不会重复安装。
> 依赖装不上也**不会中断**:脚本会提示哪些功能不可用,服务器照常启动。

### 方式二:手动

1. 右键用**文本编辑器**打开 `config.json`,把 `shareRoot` 改成你想共享的**真实文件夹**绝对路径,
   例如 `D:/共享文件`(注意用 `/` 分隔;Windows 路径如 `D:\共享文件` 建议写成 `D:/共享文件`)。
2. 双击运行 **`start.bat`**。
   - 首次运行会自动调用 OpenSSL 生成 `certs/server.crt`(有效期约 397 天,到期后重新运行一次即可)。
   - 若提示没有 openssl,请安装 Git for Windows 或 Win64 OpenSSL 后重试;也可以改用命令
     `npm run cert`。
3. 启动后窗口会打印访问地址,例如:

   ```
   本机访问  : https://localhost:8443/
   局域网访问: https://192.168.1.100:8443/
   IPv6 访问 : https://[2001:db8:abcd:1234:5a6b:7c8d:9e0f:1a2b]:8443/
   监听方式  : IPv4 + IPv6 双栈  (IPv6 设备的浏览器可直接访问上面列出的 IPv6 地址)
   ```

   - **IPv4 与 IPv6 都会列出来**:有 IPv6 网卡(家用宽带、手机热点大多已支持)时,除了
     `https://192.168.x.x:8443/`,还会给出 `https://[2001:db8:...]:8443/` 这样的 IPv6 地址 ——
     局域网设备哪个能通就用哪个。IPv6 地址要**带上方括号**才能写进 URL。
   - 链路本地地址(`fe80::/10`)必须带网卡作用域 ID(如 `%以太网`、`%12`)才能访问,
     直接给出 URL 反而点不开,所以只在末尾提示共有几个,不列出。
   - **IPv6 环境不支持时不会出问题**:服务会退回只监听 IPv4,并在「监听方式」里写明。

4. 局域网设备(须与电脑在同一局域网)在浏览器输入
   `https://192.168.1.100:8443/` 即可使用。

> 若改 `port` 配置,把上面的 `8443` 换成你的端口即可。
> 首次在**局域网设备**上打开时,浏览器会因自签名证书报警告(见第四节);主共享若设了
> 「根目录访问密码」,还会先弹出用户名/密码框(用户名随便填,只需要密码,见第七节)。

### Linux / macOS 部署要点

Linux 上**完全可用**(核心就是一个 Node 脚本,没有 Windows 专有依赖),但有几处和 Windows 不同:

```bash
git clone https://github.com/zsy1023/lan-file-share.git
cd lan-file-share
./setup.sh          # 仓库已带可执行位;若从旧的克隆里更新,用 bash setup.sh 或 chmod +x setup.sh

# 不想跑一键安装、只想起服务:
node server.js
```

| 注意点 | 说明 |
|---|---|
| **Node 版本** | 建议 **Node 20 / 22 LTS**。Linux 的「递归目录监视」(实时静默同步)需要 Node ≥ 19.1;Node 18 上启动会提示「当前文件系统不支持递归目录监视」,此时只有本服务自己的写入会实时同步,其余功能不受影响 |
| **OpenSSL** | `gen-cert.js` 用了 `openssl req -addext`,需要 **OpenSSL ≥ 1.1.1**(Ubuntu 20.04+ / Debian 11+ / RHEL 8+ 自带即满足;CentOS 7 的 1.0.2 会失败) |
| **防火墙** | `sudo ufw allow 8443/tcp`(Fedora:`sudo firewall-cmd --add-port=8443/tcp --permanent && sudo firewall-cmd --reload`)。**单独分享的端口**(默认从 9000 起)也要放行 |
| **证书信任** | 见第四节「方式 B」里的 Linux 命令(Debian/Ubuntu 用 `update-ca-certificates`,Fedora/RHEL 用 `update-ca-trust`);Chrome / Firefox 可能还有各自的证书库 |
| **低端口** | `port` < 1024 需要 root 或 `setcap`;默认 8443 不受影响 |
| **后台常驻** | `setup.sh` 是前台运行;要常驻可用 `nohup node server.js > log.txt 2>&1 &`、`screen` / `tmux`,或自行写一个 systemd 服务 |
| **仅 Windows 的功能** | 分享面板里的「📂 分享本机其他文件夹…」用 Windows 原生文件夹选择框,Linux 上会提示失败,改为**手动填写绝对路径**(功能本身照常可用) |
| **文件名差异** | Linux 允许文件名里含 `\`,而程序会把 `\` 当路径分隔符归一化,这类文件名在网页上可能打不开(极罕见) |

## 三、局域网设备如何用

| 操作 | 方法 |
|------|------|
| 下载 | 点文件名即可下载;图片可点缩略图放大查看(**先秒开低清预览,高清原图随后自动替换**);视频点封面可在页内播放 |
| **文本预览** | txt / 日志 / md / json / 代码等文本文件点右侧 **「预览」**(或图标视图里点 📄)即可在页内查看内容,不用先下载;只读前 1MB,UTF-8 / GBK 自动兼容 |
| 新建文件夹 | 工具栏 **「＋ 新建文件夹」**,在当前目录下建一个文件夹(只读访问时不显示) |
| **批量下载** | 每行/每个格子左上角有勾选框,勾选后可点工具栏的 **「⬇ 下载选中」**:**只勾一个文件就直接下原文件(不打包)**;勾多个或勾文件夹才打包成 ZIP。文件夹会被**递归**打包(含内部所有子文件)。下载过程会显示**真实进度**(已下载 / 总计 / 百分比),且**支持断点续传**(中断了能接着下) |
| 视图 | 顶部工具栏可切换「列表 / 图标 / 平铺 / 缩略图」,并用滑块调整图标大小,选择会被记住 |
| 上传文件 | 点顶部“选择文件上传”**或把文件拖进页面**,支持多选;同名文件会覆盖。**大文件自动分片传输,支持断点续传与失败自动重试**(详见下文) |
| 上传文件夹 | 点顶部“📂 上传文件夹”选中整个文件夹,程序自动按原目录结构上传(空子目录不自动创建) |
| 重命名 | 点该行右侧“重命名”,输入新名称 |
| 删除 | 点该行右侧红色“删除”;文件直接删除,目录连同内部全部内容一并删除。页面会弹确认框,一旦确认即**永久删除、不经过回收站,无法恢复** |
| 进入子目录 | 点目录行进入;顶层面包屑可快速回到上级目录 |
| 断点续传 | 下载支持 Range,下载中断后浏览器续传会生效 |
| **自动同步** | 页面右上角显示“已同步”时:无论**谁**改了共享目录(别人上传/删除/重命名,或你在资源管理器里直接改文件),所有正在浏览的页面都会**自动静默更新列表,无需手动刷新**。刚变化的文件行会短暂高亮一下 |
| **单独分享文件夹** | 点某个文件夹行右侧的「分享」,可把它**单独开一个端口**对外共享(功能与主页面完全一致:浏览/上传/下载/删除/重命名/预览/自动同步)。仅**本机**网页端能创建与取消 |

> 提醒:本版本已加入**删除 / 重命名 / 上传文件夹**能力,与早期“仅浏览/下载/上传”不同——所以任何能访问该网址的设备都能改动并**永久删除**共享目录里的内容(操作前有一道浏览器确认框)。请只对**可信局域网**开放,并谨慎操作系统(建议可另设一个专属共享目录,而非散放所有个人文件夹)。若不想让局域网里任何设备都能直接读写,可以在本机网页端设一道
> 「根目录访问密码」(见第七节);单独分享也可以各自设口令。

## 四、关于 HTTPS 证书的信任提示(重要)

自签名证书**不是由权威机构签发**,所以浏览器首次访问会提示“连接不是私密连接 / 证书不受信任”。
这是自签名证书的**正常现象**,你有两种处理方式:

### 方式 A —— 最快:临时放行(推荐先这样看是否可用)

以 Edge / Chrome 为例:访问 https 地址 → 出现警告页 → 点“高级”→“继续前往 xxx(不安全)”。
以后每次访问可能还要再点一次(设备重启后 Chrome/Edge 偶尔需要重新点)。

### 方式 B —— 一劳永逸:把证书装进信任库(推荐正式使用)

把电脑上的 `certs/server.crt` 分享到各设备,并安装为“受信任的根证书”,之后浏览器不再有警告。

- **Windows 设备**:双击 `server.crt` → “安装证书”→“本地计算机”→“将所有证书放入下列存储”→
  选“受信任的根证书颁发机构”→ 完成。
- **Android**:设置 → 安全 → 加密与凭据 → 安装证书 → 选择 `server.crt`(需与电脑传输该文件),
  有的系统叫“从存储设备安装 CA 证书”。
- **iPhone/iPad**:把 `server.crt` 用邮件 / 浏览器 / 数据线传上设备 → 设置描述文件并安装 →
  再到“设置-通用-关于本机-证书信任设置”里**启用完全信任**。
- **macOS**:双击 `server.crt` → 钥匙串访问 → 把证书标记为“始终信任”。
- **Linux**(装进系统信任库):
  ```bash
  # Debian / Ubuntu
  sudo cp certs/server.crt /usr/local/share/ca-certificates/lan-file-share.crt
  sudo update-ca-certificates

  # Fedora / RHEL / CentOS
  sudo cp certs/server.crt /etc/pki/ca-trust/source/anchors/lan-file-share.crt
  sudo update-ca-trust
  ```
  浏览器可能还有自己的证书库:Firefox 需在「设置 → 隐私与安全 → 证书 → 查看证书 → 证书颁发机构 → 导入」里单独导入一次。

> 说明:证书里已自动包含本机在局域网内的 **IPv4 与 IPv6 地址**以及 `localhost`
> (生成时实时扫描网卡),一般无需手动改;若后来又换网段,请删除 `certs/*` 后重新运行
> `node gen-cert.js` 或再次运行 `start.bat` / `setup.sh`。

## 五、配置项说明(config.json)

| 字段 | 默认 | 说明 |
|------|------|------|
| `shareRoot` | 本目录下的 `share` | 要共享的文件夹绝对路径 |
| `port` | `8443` | 主共享的监听端口。用大端口不需要管理员权限;注意 Windows 防火墙要放行该端口 |
| `certFile` / `keyFile` | `certs/server.crt` / `certs/server.key` | 证书 / 私钥相对本目录的路径 |
| `maxUploadMB` | `0` | 单个文件上传上限(MB)。`0` 表示不限制 |
| `allowOverwrite` | `true` | 是否允许同名文件被覆盖上传。设 `false` 则同名返回冲突 |
| `logLevel` | `normal` | 操作日志详细程度,见下表 |
| `sharePortBase` | `9000` | 单独分享文件夹时,自动分配端口从这个值往上找空闲端口 |
| `title` | 局域网文件共享 | 网页标题与顶部名称 |

> 「根目录访问密码」**不在 config.json 里**:它是运行时设置项,在**本机网页端**
> 点右上角「🔒 访问密码」即可开启/修改/取消,立即生效,记录写在同目录的 `rootauth.json`(见第七节)。

### 操作日志详细程度(`logLevel`)

日志会打印到**启动窗口**(带颜色),同时可在网页右上角点「📋 操作日志」查看最近 300 条。
每条日志形如:

```
[2026-10-01 13:31:32] [WRITE] 上传文件 成功 谁: 192.168.1.23(DESKTOP-ABC) | 设备: Windows 10/11 · Edge | 位置: 主共享:8443 /照片 | 2.4 MB
```

即「谁(IP 与反向解析的主机名)、用什么设备(系统与浏览器)、在哪里(哪个共享/哪个端口/哪个目录)、做了什么、结果如何」。

**级别标签按行为着色**,便于在刷屏中一眼分辨:

| 标签 | 颜色 | 含义 |
|------|------|------|
| `[WRITE]` | 绿/黄/红 | **写操作**:上传、删除、重命名、新建目录(会改动磁盘,最需要留意) |
| `[READ]` | 青色 | 下载、预览 |
| `[BROWSE]` | 灰色 | 浏览目录(高频、信息量低) |
| `[SHARE]` | 紫色 | 分享管理:创建/取消分享、改口令、改端口 |
| `[DENY]` | 红色 | **拒绝访问**:口令错误、路径非法、权限不足、尝试写只读分享 |
| `[ERROR]` | 红色 | 服务端异常(通常附完整堆栈) |

`[WRITE]` 与 `[DENY]` 会重点标色;失败的行整行标红,方便一眼扫到。
时间戳与级别都带方括号,便于 grep 与过滤,例如只看写操作与拒绝:

```bash
node server.js | grep -E '\[(WRITE|DENY)\]'
```

| 级别 | 记录内容 |
|------|----------|
| `quiet` | 只记录**写操作**(上传 / 删除 / 重命名 / 新建目录)与分享管理 |
| `normal`(默认) | 写操作 + 目录浏览、下载、预览 + **拒绝访问** |
| `verbose` | 再额外记录服务端异常等排查信息 |

> 客户端 IP 取自 TCP 对端地址,不会被 `X-Forwarded-For` 之类的请求头伪造。
> 主机名来自反向 DNS 解析,解析不到时只显示 IP(解析失败不会拖慢请求)。

### 终端颜色

- **重定向到文件或管道时自动关闭颜色**,所以 `node server.js > log.txt` 得到的日志
  不会混入 ANSI 转义字符,用记事本/grep 看都很干净。
- 想强制开启:`FORCE_COLOR=1 node server.js`
- 想彻底关闭:`NO_COLOR=1 node server.js`
- Windows 10/11 的终端默认支持 ANSI 颜色;若在很旧的 conhost 里显示成乱码,设 `NO_COLOR=1` 即可。

## 六、单独分享文件夹

把一个子文件夹单独开一个端口对外共享,适合「只把某个文件夹给某几个人」的场景。

- **怎么分享**:在主页面列表里,点目标文件夹行右侧的 **「分享」** → 弹窗里可填端口(留空自动分配)、
  可选设访问口令 → 点「开始分享」,随后会弹出窗口显示**访问地址**(含本机与各局域网 IP,可一键复制)。
- **功能**:该端口上浏览 / 上传 / 下载 / 删除 / 重命名 / 预览 / 实时静默同步**与主页面完全一致**,
  只是根目录变成了那个子文件夹,且**无权访问该文件夹之外**的任何内容。
- **谁能创建**:仅**本机网页端**。本机无论用 `https://localhost:8443/`、`https://127.0.0.1:8443/`
  还是本机自己的局域网 IP 访问,都能创建;其它设备即使是同一网段也会被服务端拒绝(403)。
- **不能嵌套**:已经分享出去的文件夹(及其内部任意层级)不能再分享一次,服务端会直接拒绝。
  主页面里这类文件夹的「分享」按钮也会置灰。
- **两种口令(读写 / 只读)**:创建分享时可以**分别**设两个口令,把不同的口令给不同的人:
  - **读写口令** —— 可浏览、下载、上传、删除、重命名、新建目录(全权限)
  - **只读口令** —— 只能浏览、下载、预览;**上传/删除/重命名一律被拒绝**(服务端拦截,前端也会隐藏这些按钮和上传区)
  两个口令不能设成相同。也可以只设其中一个:只设只读口令时,整个分享就是只读的。
- **随时取消**:右上角「🔗 单独分享」面板里可查看所有分享、复制地址、**分别改读写/只读口令**、改端口、
  **取消分享**(取消只关闭那个端口,不会删除文件)。
- **退出登录**:用口令进入该端口后,右上角同样有 **「🚪 退出登录」**,点了会清掉浏览器保存的口令。
- **重启保留**:分享记录保存在同目录的 `shares.json`(只存口令的哈希,不存明文),重启后自动恢复;
  若目录已被删除或端口被占用,只跳过这一条并在启动窗口提示,不影响主服务。

## 七、根目录访问密码(可选,只保护局域网访问)

不想让局域网里任何设备都直接读写共享目录时,给**主共享**加一道密码。

- **怎么开**:在**本机**打开主页面,点右上角 **「🔒 访问密码」** → 输入新密码(需输两次)→
  点「保存密码」。保存后**立即生效**,不用重启;点「取消密码保护」即可关掉。
  (这个入口只在**主共享页面**出现,单独分享的端口没有它,也调不动对应接口。)
- **局域网设备怎么访问**:打开 `https://<本机IP>:8443/` 时浏览器会弹出用户名/密码框
  (HTTP Basic 认证:**用户名随便填,只有密码有意义**)。密码正确后整站照常使用
  (浏览 / 下载 / 上传 / 删除 / 重命名);输错会再弹一次;**同一个 IP 连续错 6 次会被退避 60 秒**
  (返回 429),避免有人拿脚本猜密码。
- **本机免输**:从**本机**访问(回环地址 `localhost`、`127.0.0.1`、`::1`,或本机自己的网卡 IP)
  一律不需要密码 —— 判定依据是 **TCP 对端地址**,和「分享管理仅限本机」同一套逻辑,
  伪造 `X-Forwarded-For` 之类的请求头无效。
- **只管主共享**:单独分享的文件夹有各自的口令(读写/只读),不受这个密码影响;
  反过来,**没设口令的单独分享即使主共享开了密码也依然免密可访问**(端口即权限),
  需要的话请给那个分享也设上口令。
- **密码存在哪**:以 **scrypt 哈希(加盐)存在程序目录的 `rootauth.json`,不存明文**;
  重启服务后仍然有效。**忘记密码时**:删掉 `rootauth.json` 再重启即可关闭密码保护
  (如果还能进本机页面,也可以直接点「取消密码保护」)。
- **退出登录**:凭口令进入后,右上角会多出 **「🚪 退出登录」**(本机免密访问时不会出现)。
  点它会清掉浏览器记住的口令——服务端回一个 401 挑战,浏览器随即丢弃缓存的口令,下次访问要重新输入。
  **注意**:弹出登录框时要点「取消」才算真正退出;若又在框里输入了口令,等于重新登录。
  单独分享端口上用口令进入时同样有这个按钮。
- **日志**:设置/取消会记一条 `[SHARE] 修改访问密码`;局域网口令错误会记
  `[DENY] 拒绝访问 … 根目录访问密码错误或未提供`,顺利通过时日志的「位置」栏会写成
  `主共享:8443(凭访问密码)`,便于区分本机直连与局域网凭密码进入。

> 这是一道「可信局域网」上的门闩,**不是一个账号体系**:全站共用一个密码,没有用户与权限分级,
> 也不能只给某人「只读」权限 —— 要只读访问,请用单独分享的**只读口令**(见第六节)。

## 八、大文件上传与图片预览

### 大文件分片上传(断点续传 + 自动重试)

超过 **4MB** 的文件会自动走分片上传,不必担心"传到一半断掉要重来":

- **分片大小自适应**:起始 1MB,按实测网速动态调整(目标约 2 秒一片),
  范围 256KB–8MB。网快就放大分片减少往返,网慢就缩小分片降低单片失败代价。
- **断点续传**:每片收到后立即追加落盘并记录进度。中途断网、关掉浏览器、
  甚至**服务端重启**,再次上传同一文件时会从断点继续,不必重传已传部分。
  (状态存在共享目录内的 `<文件名>.uploading-chunk` 临时文件里。)
- **失败自动重试**:单个分片失败会自动重试,退避 0.5s → 1s → 2s → … 最多 6 次;
  若服务端报告的进度与客户端不一致(如响应丢了),会以服务端进度重新对齐。
- **原子落盘**:所有分片收齐后,服务端把临时文件一次性改名为目标文件,
  所以列表里不会看到"半截文件"。

### 图片低清预览

装了 `sharp` 后,上传图片会顺带生成一张低清预览图(长边 960px 的 JPEG),
于是打开大图时:

1. **低清图先秒开** —— 顶部会提示「正在显示低清预览图(画面可能有压缩),高清原图加载中…」
2. 高清原图在后台继续下载,就绪后**自动替换**,提示消失

这样即使原图几十 MB,点开也能立刻看到画面,不用干等。

> 低清图以 `<原文件名>.thumb.jpg` 存在图片同目录,但它是**内部文件**:
> 不会出现在网页列表里,也不能被下载 / 删除 / 重命名;删除或重命名原图时它会一起联动。
> 若某个图片的缩略图不存在(例如未装 sharp 时传的),第一次访问 `/thumb` 会现场生成。

### 视频封面预览

装了 **ffmpeg** 后(可选),视频文件也会有一张封面图:

- 列表 / 图标 / 平铺 / 缩略图视图里,视频显示为**抽帧封面**(而不是 🎬 图标)
- 封面由 ffmpeg 抽取**第 1 秒**那一帧(很多视频开头是黑屏,取 1 秒更容易拍到有内容的画面;
  视频不足 1 秒时自动回退到第一帧),同样压成长边 960px 的 JPEG,与图片缩略图共用一个文件
- 点击封面会在预览层里用**原生播放器**播放(支持拖动进度条,靠 `/raw` 的 Range 支持)

> ffmpeg 是可选的:没装就跳过,视频仍显示 🎬 图标,不影响其它功能。
> 服务启动时会在日志里报告「视频封面 已启用 / 未启用」。
> 若 ffmpeg 不在 `PATH` 里,可用环境变量 `FFMPEG_PATH` 指定完整路径。

### 文本预览(txt / 日志 / 配置 / 代码)

不用先下载就能看内容:

- 列表里这类文件右侧有 **「预览」** 按钮;图标视图里点 📄 图标也能直接打开。
- 支持 `txt` `log` `md` `json` `csv` `xml` `yml` `ini` `conf` `sql` `js` `css` `html`
  `bat` `ps1` `sh` `py` `java` `c` `cpp` `go` `rs` 等常见文本格式,以及无扩展名的
  `README` / `LICENSE` / `Dockerfile` / `.gitignore` 之类。
- 预览层里是**只读**的等宽展示(长行自动换行、可滚动),← / → 可以在同一目录的
  图片、视频、文本之间连续切换;Esc 或点空白处关闭。
- **只读取前 1 MB**:超大日志不会把浏览器卡死,超过时顶部会提示「只预览前 1 MB,需要全文请下载」。
- **编码自动兼容**:优先按 UTF-8 解码,失败自动退回 GB18030 —— 中文 Windows 用记事本
  存的 txt 多半是 GBK,直接按 UTF-8 读会成乱码,这里已经处理。
- 内容用 `textContent` 渲染(而不是 innerHTML),HTML/JS 文件只会以**源码文本**显示,
  不会被执行,不存在 XSS 风险。

### 预览缓存(ETag / 304)

预览原图与缩略图都带 `ETag` 与 `Last-Modified`:

- **再次打开同一张图不会重新下载** —— 浏览器直接用本地缓存;即使缓存过期,也只会收到
  一个体积为 0 的 `304` 响应,而不是重新传整张原图
- 文件被**同名覆盖**后 `ETag` 随之变化,浏览器会自动重新拉新图,**不会看到旧图**
- 此外前端还有一层**内存缓存**(同一页面会话内最近 12 张原图),重复预览时零网络请求

> 这一层对走内网穿透(隧道)的场景尤其重要:隧道带宽通常远低于局域网,
> 避免重复传输原图能显著改善预览体验。

### 批量下载(ZIP 打包)

想一次拿走多个文件或整个文件夹时:

1. 在列表(或图标/平铺/缩略图视图)里**勾选**需要的条目 —— 每行行首、每个格子左上角都有复选框;
   也可以用「全选」一次选中当前目录的全部内容。
2. 点工具栏的 **「⬇ 下载选中」**:
   - **只勾了一个文件** → **直接下载原文件,不打包**(不用等打包、也不占临时磁盘);
   - **勾了多个条目或文件夹** → 服务端打包成 ZIP 再下载(文件夹必须打包才能一次拿走)。

细节说明:

- **文件夹会递归打包**,包含其内部所有层级的子文件;空目录也会保留。
- **压缩包保留目录结构**:例如在根目录勾选 `文档/a.txt` 与 `照片` 文件夹,解压后得到
  `文档/a.txt`、`照片/p1.txt`、`照片/子目录/deep.txt` —— 层级与原目录一致,解压不会散成一堆。
- **不会多套一层**:选中 `照片` 打包,解压出来就是 `照片/...`,而不是 `照片/照片/...`。
- 包内**不含**本服务自动生成的缩略图等内部文件。
- 选中项里若有个别已被删除/无权限,会**跳过它并继续打包其余内容**,不会让整次下载失败。
- 一次最多 500 项。
- 压缩包名:单项时用该项名字;多项时用「当前目录名_项数.zip」。
- **打包很快**:局域网传输不必为了省几个字节烧 CPU ——
  已经是压缩格式的(jpg / png / mp4 / mp3 / zip / pdf / docx / apk …)直接**存储**、不再二次压缩,
  其余(文本、日志等)只用 deflate **最快档**。实测 220 个文件 / 160 MB 从 7.2 秒降到 0.7 秒
  (约 220 MB/s,基本是磁盘速度),而文本照样能压到原来的 1% 左右。
- **提示会跟着真实进度走**:打包阶段显示「已处理 N 项 / 共 M 项」,开始下载后显示
  **「正在下载… 12.3 MB / 160.1 MB (8%)」**,只有真的传完才显示「下载完成」;
  中途断开会立刻显示「下载中断…」,重新点一次即可续传。
- **支持断点续传**:下载的是一个普通文件地址(带 `Accept-Ranges`),
  所以**下载中断、暂停、甚至关掉浏览器再回来都能接着下**,不会整个包从头再来;
  也支持下载工具多线程拉取。
- **两段式流程**:先由服务端把 ZIP 打包好,完成后再开始下载 —— 这是为了换取「断点续传」的能力。
- **打包结果可以复用**:同一个选择在 6 小时内重复点「下载选中」,会直接复用已打好的包,不必重新压缩。

> 为什么不做「边压边传」:ZIP 的目录索引写在文件末尾,流式响应没有随机定位能力,
> 一旦中断就只能从头重传。对几十 GB 的目录来说这在实际使用中不可接受,所以这里选择先落盘。
> 打包临时文件存放在**系统临时目录**(`%TEMP%\lan-file-share-zips`,不在共享目录里),
> 完成后保留 6 小时,过期自动清理。

> 需要 `archiver` 依赖。没装时「下载选中」会提示不可用,但**单文件下载完全不受影响**。

## 十、高级 / 运维提示

- **Windows 防火墙**:首次运行若其它设备连不上,请确认已在系统防火墙中放行所用的 TCP 端口;
  浏览器访问的是目标电脑的**局域网 IP** 而不是 `localhost`。
- **IPv6**:服务默认**双栈监听**,所以同一个端口在 IPv4 与 IPv6 上都可用。
  - 系统防火墙对 IPv4 与 IPv6 是**分开设置的**:只用 IPv6 连不上时,记得也放行 IPv6 的对应端口
    (Windows:高级安全 Windows Defender 防火墙 → 入站规则,协议 TCP、本地端口填你的端口)。
  - **链路本地地址**(`fe80::/10`)必须带上网卡作用域 ID 才能访问,例如
    `https://[fe80::1a2b:3c4d:5e6f:7a8b%以太网]:8443/`(浏览器里 `%` 也可写成 `%25`),
    所以启动时只提示共有几个,不直接列出 URL。
  - 证书的 SAN 现在**同时包含 IPv4 与 IPv6 地址**,用 IPv6 地址访问不会再报「证书名称不匹配」;
    但**临时 IPv6 地址(隐私扩展)会不定期变化**,变了之后旧证书就对不上 —— 重新运行一次
    `node gen-cert.js` 生成新证书即可,或者干脆用 IPv4 地址访问。
  - 若系统完全没启用 IPv6,启动日志里的「监听方式」会写明「仅 IPv4」,服务照常可用。
- **换个端口**:改 `config.json` 的 `port` 后重启即可,无需重新生成证书(证书含 IP 不含端口)。
- **换网段 / IP 变了**:重新生成证书即可(SAN 只认旧 IP 的话设备会校验失败)。
- **公网暴露风险**:程序**没有账号体系**,仅供可信局域网内使用。请**不要**把端口映射到公网。
  想挡住局域网里信手拈来的访问,可以用「根目录访问密码」(第七节)或给单独分享设口令,
  但这只是可信网络里的一道门闩,不能当作面向公网的安全措施。
  如需他人同时在线、限制速度或支持 WebSocket 断点续传上传,可后续扩展。
- **实时同步**:服务对共享目录做了递归 `fs.watch`,并在每个写接口后主动广播;浏览器用 SSE
  (`/api/events`)接收。若某个文件系统不支持递归监视,启动时会提示,此时仅“本服务自身的写入”会实时同步。
  每个端口只收到**自己作用域内**的变更:单独分享端口不会收到其它目录的动静。
- **单独分享的端口**:每个分享都会额外监听一个 HTTPS 端口,记得在系统防火墙里放行这些端口。
- **日志会写 IP**:操作日志包含访问者 IP 与反向解析的主机名;若你不想记录这些,把 `logLevel` 调成 `quiet`
  仍会记录写操作,或改用更严格的网络隔离。
- **大上传 / 较慢**:上传采用流式写入磁盘,不占用大量内存;下载走流式 + 支持断点续传。

## 十一、目录结构安全

- 所有请求路径都经过 `realpath` + 越界校验,不能通过 `../`、符号链接/目录联接等访问共享目录之外的文件。
- 上传拒绝含 `/`、`\`、空字节、`.` `..` 的名称;Windows 上另外拒绝 `: * ? " < > |`、结尾的点/空格
  与 `CON/PRN/AUX/NUL/COM1..9/LPT1..9` 保留名(避免写到 NTFS 备用数据流或残留 0 字节同名文件)。
- 上传先写临时文件再原子改名,客户端中断不会留下半截假成功文件。
- 删除仅限共享目录内路径,禁止删除共享根自身;删除/重命名只在解析后的真实共享内路径执行。删除为**永久、递归**(目录整体),不可恢复;
- HTML / SVG / JS 等**可执行内容一律以附件形式下发**,`/raw` 预览另加 `CSP sandbox` 与 `X-Content-Type-Options: nosniff`,
  从根上消除共享目录内文件造成的存储型 XSS。
- 目录创建与上传同受限在共享根内,不能通过 `../` / 空段逃出。
- **单独分享端口有自己的根**:该端口上一切路径都被限制在被分享的那个子文件夹内,`../`、
  兄弟目录、共享根之外的路径一律 403;功能与主页面一致但视野更小。
- **分享管理仅本机**:创建/取消分享、改口令、看日志这些接口都会校验 TCP 对端地址是否属于本机
  (回环地址或本机自己的网卡 IP),其它设备访问一律 403;伪造 `X-Forwarded-For` 无效。
- **根目录访问密码(可选,见第七节)**:一旦设置,**主端口上非本机来源**的每个请求都先做
  HTTP Basic 校验 —— 口令用 **scrypt 加盐哈希**保存(不存明文)、用**常量时间比较**,
  同一 IP 连续输错 6 次会在 60 秒内直接返回 429(避免被脚本反复猜);校验本身也限并发,
  不会因为有人猛试口令而拖垮服务。本机来源(回环与本机自己的网卡 IP,按 TCP 对端地址判定)
  不需要密码,和「分享管理仅限本机」用的是同一套判定;设置/取消密码的接口同样仅限本机。
- **不能嵌套分享**:已分享文件夹及其内部任何层级都无法再次分享,且这一限制在服务端强制执行。
- **缩略图/视频封面是内部文件**:`<原名>.thumb.jpg` 不出现在列表,也不能通过 `/download`、`/raw`、
  `/api/delete`、`/api/rename` 访问或改动;它只能经 `/thumb?path=<原图路径>` 取得,
  该接口同样受路径越界校验保护,并带 `CSP: sandbox` 与 `nosniff`。
- **分片上传同样受限**:`/api/upload/chunk`、`/api/upload/finish`、`/api/upload/status`
  都走与普通上传相同的目标目录校验,不能借分片接口写出共享根。
- **批量打包同样受限**:`/api/download-zip` 的每一项都独立做越界校验(路径穿越会被拒/跳过),
  压缩包内的条目名只取共享根内的相对路径,**不含盘符或 `..`**,因此解压时不会写到目标目录之外
  (防 Zip Slip);递归打包时**跳过符号链接**,避免顺着链接把共享根外的内容打进包里。

### 已知边界(这是“可信局域网工具”,不是公网服务)

- **主共享默认没有鉴权**:不设「根目录访问密码」时,局域网内任何设备都能浏览、上传、重命名、
  永久删除主共享内容;设了之后也只是**挡住局域网来源**(本机免输),并且全站共用一个密码、
  没有用户与权限分级。(单独分享**可选**口令,还能区分读写/只读,但那是为“分享给少数人”
  设计的隔离手段,不是完整的账号体系。)
- 服务以启动它的用户身份读写文件,**不隔离权限**;请只共享一个专用目录,不要指向系统盘根或用户目录。
- 不校验上传内容,不上病毒扫描;上传的文件可被任何人下载。
- 单独分享是“端口即权限”:不设口令时,任何能访问该端口的设备都能使用,请按需设置口令。
